# Selector Showdown — Visual-Only Street Fighter III Audit

The current cabinet has strong arcade material cues, but the active Level 1 presentation falls short of the requested fighting-game-stage standard. In the live playfield, the supplied stage art occupies only a shallow upper band, leaving a large dark unused field below it. The selector sprite is readable but suspended near the top of the action area rather than grounded in a layered stage composition. Active pickups read as isolated icons instead of props integrated through shared outline, shading, and impact language.

The visual-only pass will preserve all item classes, DOM structure, state names, physics, audio, scoring, controls, progression, persistence, and timers. It will improve the established art presentation through CSS and existing asset framing only: full-height stage depth, parallax-like foreground silhouettes, hard cel-shaded planes, inked outlines, palette ramps, floor contact shadows, impact glints, and improved environmental layering. The cabinet structure and all UI copy remain functionally unchanged.

The image-generation route was unavailable because the daily generation quota had already been reached. The implementation therefore uses the existing approved arcade artwork and a scoped CSS art pass only. The active Level 1 test confirmed that the new treatment needs to solve the original shallow-stage problem: the selector must feel grounded in a foreground floor plane, while the rave environment remains readable behind falling pickups. The changes added a hard-edged perspective floor, stage-side silhouettes, crowd depth, cel-shaded outlines, and stronger prop treatment without editing the component logic.

The post-change active Level 1 check shows the selector enlarged and grounded against the new floor plane, with the stage art spanning the full playfield rather than reading as a shallow top strip. The cabinet, score, reset, and supporter controls remained in their existing locations and the session continued through its normal game-over and reset flow, providing a visual confirmation that the CSS-only changes did not replace game infrastructure.

The existing selector regression guard, TypeScript check, and production build all passed after the visual work. The browser-console review found no warnings or errors. The final independent visual review judged the broader design to remain cohesive and advised shipping the result. The only uncompleted route was custom generated stage imagery, which was blocked by the daily generation limit; the CSS-only refinement remains fully functional and uses only the existing approved assets.
